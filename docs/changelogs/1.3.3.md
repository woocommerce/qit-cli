### QIT CLI 1.3.3 Release Notes

#### Improvements

- `run:woo-api` picks its test package from the WooCommerce version under test, as `run:woo-e2e` and `run:activation` already do. Until now every Woo API run used `woocommerce/core-api-tests:latest`, so a run on a WooCommerce release candidate executed the specs written for the previous line and reported upstream changes as failures of the extension under test. A version ahead of every published line, such as `nightly`, takes the `nightly` package.
- `qit compare` renders the comparison computed by the QIT Manager, with the same sections and names as the report page, and ends with a link to it. Runs that are not comparable end with *Not comparable* instead of a verdict; `--exit-code` still exits 1 on regressions. `--format=json` prints the Manager's document as is.
- `qit compare` shows the canary profile of ecosystem canary runs and refuses to call two runs comparable when they ran against different stores.
- A plugin or theme passed as a local directory or zip (`--source`/`--zip`) is reported with the version in its `Version:` header instead of `undefined`.

#### Bug Fixes

- The second and later `run:e2e` of the same extension zip within its cache window passed an empty `QIT_SUT_ENTRYPOINT` to test packages. The entrypoint is now detected on a cache hit too, so the activation package finds the extension under test when WordPress's slug differs from QIT's.
