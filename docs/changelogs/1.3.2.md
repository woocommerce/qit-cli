### QIT CLI 1.3.2 Release Notes

#### New Features

##### Define local environments from WordPress Playground Blueprints

Local QIT environments can be defined with a [WordPress Playground Blueprint](https://developer.wordpress.org/playground/blueprints/):

```bash
qit env:up --blueprint=./blueprint.json
qit run:e2e my-plugin --blueprint=./blueprint.json --test-package=./my-tests
```

No Playground is involved — the Blueprint is translated into a normal QIT Docker environment. `blueprint:import` and `blueprint:export` expose the conversion in both directions without booting anything, so a QIT environment can also be shared back as a Playground link.

Supported on `env:up`, `run:e2e`, `run:woo-e2e` and `run:woo-api`, for e2e environments only.

##### Added `qit compare` for diffing two finished test runs

`qit compare <run-a> <run-b>` diffs two finished test runs without re-running anything:

```bash
qit compare 12345 12346
qit compare 12345 12346 --format=json --exit-code
```

It reports introduced, resolved and still-failing tests; tests added or removed; summary counts side by side; and a per-test diff of `extra.annotations`. The diff works on CTRF test names and statuses, so it serves every CTRF-reporting test type.

Ecosystem canary runs get two extra rules. A finding whose signature moved to a different probe is reported as moved rather than as a regression and a fix at once. A baseline finding missing from a probe that stopped early is reported as unverified rather than resolved.

#### Improvements

- `run:woo-e2e` and `run:activation` pick their test package from the WooCommerce version under test instead of always using `latest`, so a run on 11.0.1 no longer executes specs written for 11.1.
- A WooCommerce version ahead of every published line, such as a nightly or a prerelease, takes the `nightly` activation package instead of falling back to `latest`.
- `qit list-tests` runs again. It sends a `test_types` filter only when one is given, and rejects unknown types locally, naming the allowed values.
